# Embedded MeshCore validation — 13 October 2026

- **ESP32S3 cross-build passed:** `BeeLink_Xiao_S3_WIO` against official MeshCore `a366955cb2f67b8e6842d4f00d2b6a554dddd88a`, PlatformIO 6.2.0, Espressif32 platform 6.11.0, Arduino ESP32 2.0.17 and Xtensa GCC 8.4.0. Successful final link and ESP32S3 image generation. Final source includes the public-key exclusion and full GNSS calendar/time bounds.
- Linker-reported static RAM is 40,728 / 327,680 bytes; flash is 639,349 / 3,342,336 bytes. These figures do not measure runtime heap, task stacks or future CAN/SD capture memory.
- The build used `BEELINK_GNSS_RESET_ISOLATED=1` to exercise compilation only. No physical reset isolation was performed or verified, no firmware was flashed, and no radio transmission occurred. The generated image is retained only in the development scratch clone; it is not published as a hardware-validated binary.
- Native Mac tests passed with `clang++ -std=c++11 -Wall -Wextra -Werror test_policy.cpp -o test_policy && ./test_policy`. They check scheduling, default disable, jitter limits, no backlog, long uptime, GPS privacy, timestamp age, invalid/simulated values, coherent coordinates and UTC eligibility.
- Three Python USB-protocol tests passed: enable/disable/query encoding, settings bounds/private acknowledgement, and framed status/error decoding. No physical USB port was opened by these tests.
- All 36 existing receiver/bridge tests passed after integration. Browser inspection confirmed the controls are explicitly labelled for the receiver, with a separate note for on-bike USB settings. Offline preview and saved screenshot were updated.
- The Mac-hosted Qwen2.5 Coder model drafted the interval gate. Review repaired its omission of the interval after the first attempt and made the header safe to include in multiple compilation units. The native test specifically guards against the missing-interval defect. The initial Kali model request produced reasoning without code and was not used as an implementation or validation result.
- Windows compiler launch failed from the long project/toolchain path; short local junction paths resolved it. The first full link exposed non-inline definitions in a dependency header; the module now uses the documented public key bytes directly instead of including that header. An upstream Melopero/Wire overload warning was observed; no vendor source was edited.

Not verified: actual board revision/pin continuity and GNSS-reset isolation, radio/GNSS bring-up, NMEA reception/fix quality, private-channel reception, regional radio configuration, real CAN SOC, SD logging, latency under capture load, power/sleep behaviour, runtime reliability or phone controls. The module does not yet implement the complete on-bike capture design.
